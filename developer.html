Getting Started

Overview

The GSM Pay API lets you accept USDT, USDC, and Binance Pay payments directly from your application. Create a checkout session server-side, redirect your customer to the hosted payment page, and receive a webhook the moment funds settle.

Base URL
https://gsmpay.io/api
Request format
application/json
Avg. settlement time
1.8 seconds

Integration flow

01
Create Checkout

Create a session from your backend with customer & invoice details.

02
Redirect Customer

Send the customer to the hosted checkout URL to complete payment.

03
Verify & Fulfil

Receive the webhook, verify server-side, then fulfil the order.

Getting Started

Authentication

Every request must include your api_key and api_secret in the request body. Both are available from your merchant dashboard under Settings → API Keys.

Keep your secret key private. Never expose api_secret in client-side code or public repositories. Store it as an environment variable.
.env 
GSMPAY_API_KEY=your_api_key_here
GSMPAY_API_SECRET=your_api_secret_here

Payments

Create Checkout

POST
/api/create-checkout

Creates a new checkout session and returns a hosted payment URL. Redirect the customer to checkoutUrl to complete the transaction.

Parameters

Name Type Description
api_key string required Your merchant API key
api_secret string required Your merchant API secret
amount decimal required Transaction amount in USD
product_name string required Name of the product or service
customer_name string required Full name of the customer
customer_email string required Customer's email address
invoice_id string required Your internal invoice / order ID
webhook_url string required Server-to-server callback URL
success_url string required Redirect URL after successful payment
cancel_url string optional Redirect URL if customer cancels
failed_url string optional Redirect URL on failed payment

Example request

$response = Http::post('https://gsmpay.io/api/create-checkout', [
    'api_key'        => env('GSMPAY_API_KEY'),
    'api_secret'     => env('GSMPAY_API_SECRET'),
    'amount'         => 10,
    'product_name'   => 'iTunes Gift Card',
    'customer_name'  => $customer->name,
    'customer_email' => $customer->email,
    'webhook_url'    => route('gsmpay_success_callback'),

    'cancel_url'     => route('gsmpay_cancel_callback'),

]);

Payments

Verify Payment

POST
/api/verify-payment

Call this endpoint inside your webhook handler to confirm a transaction before marking an invoice as paid. Always verify server-side — never trust the redirect alone.

Parameters

Name Type Description
TrxID string required Transaction ID received from the webhook
CheckoutID string required Checkout session ID returned at creation
InvoiceID string required Your internal invoice ID

Example request

PHP / Laravel 
$response = Http::post('https://gsmpay.io/api/verify-payment', [
    'TrxID'      => $request->TrxID,
    'CheckoutID' => $invoice->identify,
    'InvoiceID'  => $invoice->id,
]);
 
if ($response->successful()) {
    $data = $response->json();
 
    if (($data['Status'] ?? null) === 'Paid') {
        $invoice->update(['invoice_status' => 'Paid']);
        // grant access / fulfil order
    }
}

Events

Success Callback

GSM Pay sends a request to your webhook_url the moment a payment settles. Always re-verify the transaction using Verify Payment before fulfilling an order.

Callback payload

Field Type Description
TrxID string Unique transaction ID for this payment
CheckoutID string Checkout session ID
InvoiceID string Your invoice ID, echoed back
Status string Paid, Failed, or Pending

Handling the callback

PHP / Laravel 
function gsmpay_success_callback(Request $request)
{
    if (!$request->TrxID || !$request->CheckoutID
        || !$request->InvoiceID || $request->Status != 'Paid') {
        return redirect()->route('dashboard')->withError('Something went wrong.');
    }
 
    $invoice = Invoice::where('identify', $request->CheckoutID)
        ->where('id', $request->InvoiceID)
        ->first();
 
    if (!$invoice || $invoice->invoice_status === 'Paid') {
        return redirect()->route('dashboard')->withError('No valid transaction found.');
    }
 
    // Always re-verify server-side before fulfilling
    $response = Http::post('https://gsmpay.io/api/verify-payment', [
        'TrxID'      => $request->TrxID,
        'CheckoutID' => $invoice->identify,
        'InvoiceID'  => $invoice->id,
    ]);
 
    if ($response->successful() && $response->json('Status') === 'Paid') {
        $invoice->update(['invoice_status' => 'Paid']);
        // fulfil order / grant access
    }
}

Events

Cancel Callback

If the customer cancels checkout or the payment fails, GSM Pay redirects them to cancel_url or failed_url. No funds have moved — use this to show a friendly retry screen.

PHP / Laravel 
function gsmpay_cancel_callback()
{
    return redirect()
        ->route('dashboard')
        ->withError('Payment was cancelled. Please try again.');
}

Reference

Error Handling

GSM Pay returns standard HTTP status codes. Always check response->successful() before reading the response body.

Status Meaning
200 Request succeeded
401 Invalid API key or secret
422 Missing or invalid parameters
500 Unexpected server error — retry with backoff
